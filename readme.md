# Система Дистанционного Контроля и Прокторинга Экзаменов (ExamControl)

Данный проект представляет собой модульное клиент-серверное приложение на языке Python, предназначенное для мониторинга, удаленного управления и контроля за действиями студентов в компьютерных классах во время проведения экзаменов и лабораторных работ.

## 🛠 Архитектура проекта

Проект разделен на две независимые папки:
*   **`teacher_app/`** — серверная часть (панель преподавателя / администратора). Позволяет видеть список подключенных ПК, отправлять сообщения, блокировать ввод, запускать таймер экзамена и управлять экранами в реальном времени.
*   **`student_app/`** — клиентская часть (оверлей студента). Автоматически подключается к серверу, отображает статус, выводит кастомные уведомления, транслирует экран с аппаратным курсором и блокирует устройства ввода при заморозке.

```text
ExamControl/
│
├── teacher_app/          # Папка приложения Преподавателя
│   ├── main.py           # Точка входа сервера
│   ├── server.py         # Сетевая логика (Socket TCP)
│   ├── gui.py            # Главный интерфейс администратора
│   └── remote_window.py  # Интерактивные окна Live-трансляции и управления
│
└── student_app/          # Папка приложения Студента
    ├── main_student.py   # Точка входа клиента
    ├── client.py         # Сетевая логика клиента и эмуляция ввода
    ├── overlay.py        # Графический интерфейс и таймер студента
    └── message_window.py # Кастомное окно уведомлений
```

## 🚀 Инструкция по развертыванию и установке

### 1. Системные требования
*   Операционная система: Windows 10 / 11 (для корректной работы WinAPI).
*   Интерпретатор: Python версии 3.8 и выше.

### 2. Подготовка сетевого адреса
Перед установкой на клиентские машины необходимо узнать локальный IP-адрес компьютера преподавателя (например, с помощью команды `ipconfig` в командной строке Windows).
Откройте файл `student_app/client.py` и укажите этот IP-адрес в переменной конфигурации:
```python
SERVER_IP = "192.168.1.XX"  # Замените на реальный IP преподавателя
```
*Примечание: Если тестирование проходит на одном физическом компьютере, оставьте значение `"127.0.0.1"`.*

### 3. Установка зависимостей
Установка внешних библиотек производится отдельно для каждого рабочего места с помощью файлов `requirements.txt`:

*   **На компьютере Преподавателя:**
    ```bash
    pip install -r teacher_app/requirements.txt
    ```
*   **На компьютерах Студентов:**
    ```bash
    pip install -r student_app/requirements.txt
    ```

## 📦 Компиляция в исполняемые файлы (.EXE)

Для защиты диплома и развертывания системы без необходимости установки Python на учебные компьютеры, скрипты компилируются в монолитные `.exe` файлы с помощью утилиты `PyInstaller`.

Выполните сборку в терминале Windows (PowerShell/CMD):

1.  **Сборка панели Преподавателя:**
    ```bash
    cd teacher_app
    python -m PyInstaller --clean --onefile --noconsole main.py
    ```
    *Результат:* Готовый файл `main.exe` появится в папке `teacher_app/dist/`.

2.  **Сборка оверлея Студента:**
    ```bash
    cd ../student_app
    python -m PyInstaller --clean --onefile --noconsole main_student.py
    ```
    *Результат:* Готовый файл `main_student.exe` появится в папке `student_app/dist/`.

> ⚠️ **Важно:** Поскольку приложение студента взаимодействует с системой на низком уровне (блокировка мыши, WinAPI), запускать скомпилированный файл `main_student.exe` на машинах студентов необходимо **от имени Администратора**.

## 📖 Подробное описание работы системы

### Порядок взаимодействия модулей:
1.  **Автореконнект (Auto-Reconnect):** Клиент студента может быть запущен раньше сервера. Он циклически (раз в 3 секунды) пингует сеть. Как только преподаватель включает панель управления, студент автоматически подключается к ней без перезапуска интерфейса.
2.  **Множественный выбор (Чекбоксы):** В списке студентов на сервере преподаватель может кликами мыши отметить определенных студентов — строки визуально меняют статус с `[ ]` на `[X]`. Все последующие точечные команды (сообщения, стрим, заморозка) будут отправлены только выбранной группе студентов.

### Функциональные возможности панели управления:
*   **Управление / Live ТВ:** Открывает для каждого выбранного студента отдельное окно с трансляцией экрана в реальном времени (~10 FPS). На кадр программно накладывается контрастный курсор мыши студента. Окно перехватывает клики и нажатия клавиш преподавателя, отправляя их обратно студенту для удаленного администрирования. Кнопка «Управление» позволяет переключить окно в режим «Только просмотр».
*   **Отправить сообщение:** Выводит поверх всех окон на компьютере студента фирменное кастомное черное окно с уведомлением.
*   **Заморозить / Разморозить ПК:** Низкоуровневые хуки через библиотеку `pynput` с флагом `suppress=True` полностью перехватывают управление ОС у студента. Мышь и клавиатура перестают реагировать на физические действия пользователя до команды разблокировки.
*   **Запустить экзамен:** Активирует на оверлее студентов синхронный таймер обратного отсчета (в минутах). По истечении времени программа студента автоматически принудительно блокирует компьютер.
*   **Отключить ПК:** Корректно завершает сессию связи с выбранным клиентом и закрывает его программу.
*   **Выйти:** Безопасно останавливает сервер сокетов, извещает студентов об обрыве связи (их статус меняется на красный цвет) и закрывает приложение администратора.

## 🔬 Технические решения и WinAPI (Для пояснительной записки)

В проекте реализовано несколько ключевых решений, повышающих надежность системы защиты:

1.  **Защита от закрытия («Серый крестик»):** Обычный крестик Windows в окне студента программно деактивирован с помощью библиотеки `ctypes` и вызова функций WinAPI `GetSystemMenu` и `EnableMenuItem` (флаг `MF_GRAYED`). Кнопка становится некликбельной, что исключает случайное или намеренное закрытие программы студентом. Дополнительно перехвачена комбинация клавиш `Alt + F4`.
2.  **Единый TCP-канал данных (Base64):** Во избежание состояния гонки (race condition) и коллизий в сокетах при одновременной передаче текста и бинарных данных, кадры трансляции экрана сжимаются в JPEG и кодируются в текстовую строку Base64. Обмен идет пакетами в формате JSON, разделенными символом переноса строки `\n`.
